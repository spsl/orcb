The ORCB CLI is the `orcb` command-line interface for scripting a running ORCB editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control ORCB-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → ORCB CLI](/docs/settings). The command is `orcb` on macOS, Windows, and Linux.

Agents can install the matching Orca CLI skill with:

```bash
npx skills add https://github.com/stablyai/orca --skill orca-cli
# headless / no Settings UI:
orcb skills install --skill orca-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable Orca skill, including `orcb skills install` / `orcb skills update`.

## Install & verify

```
command -v orcb
orcb status --json
```

## Worktree commands

```
orcb worktree ps --json
orcb worktree create --repo id:<repoId> --name my-task --issue 123 --json
orcb worktree current --json
orcb worktree set --worktree active --comment "reproduced bug" --json
orcb worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [Orca CLI reference](/docs/cli/reference).

## Terminal commands

```
orcb terminal list --json
orcb terminal read --json
orcb terminal send --text "continue" --enter --json
orcb terminal wait --for tui-idle --timeout-ms 30000 --json
orcb terminal create --worktree path:/projects/app --command "npm test" --json
orcb terminal split --direction vertical --command "npm run dev" --json
```

For tracked multi-agent work, use [Orchestration](/docs/cli/orchestration) instead of plain terminal prompts.

## File commands

Open files and diffs in the active Orca worktree from a shell:

```
orcb file open src/App.tsx
orcb file diff src/App.tsx --staged
orcb file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `orcb tab profile`; start with `orcb tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `orcb automations` to create, inspect, run, and remove scheduled Orca tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in Orca account (`orcb artifacts share|update|list|delete`). Publishing is **opt-in** under Settings → Artifacts. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
orcb goto --url https://example.com --json
orcb snapshot --json     # returns refs like @e1, @e3
orcb click --element @e3 --json
orcb fill --element @e1 --value "user@example.com" --json
orcb screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
orcb set device --name "iPhone 12" --json
orcb screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through Orca's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator from `orcb emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving Orca.

```
orcb emulator list --json
orcb emulator attach "<device-name-or-udid>" --json
orcb emulator tap 0.5 0.7 --json
orcb emulator type "hello" --json
orcb emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
orcb emulator rotate landscape_left --json
orcb emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
